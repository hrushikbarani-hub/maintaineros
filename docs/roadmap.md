# Roadmap

## Shipped in 0.2

Public GitHub captures, SQLite history, score explanations, action states, dashboard, CLI, CSV/JSON/Markdown reporting, package builds and CI.

## Next focused increments

1. Store individual issue/PR evidence so recommendations link to the exact stalled work.
2. Add user-adjustable stale/release thresholds and project profiles (libraries vs applications).
3. Add score component trends and compare two captures without hiding coverage differences.
4. ETag caching, persisted import-job states and retries for larger repositories.
5. Opt-in scheduled captures and a GitHub App installation flow.

Accounts, PostgreSQL, and team ownership should follow demonstrated multi-user demand. New metrics must include coverage information and an actionable explanation.
